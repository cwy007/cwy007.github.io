# 常见问题：文件意外出现在顶部导航栏

## 现象

在项目根目录新建的普通说明文件夹（如 `docs/`）中的 Markdown 文件，在本地运行或线上部署后，文件名/标题意外出现在了博客的顶部导航栏菜单中。

## 原因分析

这是由于 Jekyll 的渲染机制与现有配置（Hux 主题）综合作用导致的：

1. **Jekyll 解析机制**：Jekyll 默认会扫描并处理项目中所有**不以 `_`（下划线）开头**的文件和目录。因为 `docs` 目录没有特殊前缀，其中的 Markdown 会被当做普通的独立网页（Page）进行编译。
2. **Title 自动推断**：即使文档中没有写 YAML Front Matter 设定 `title`，某些 Jekyll 版本或 GitHub Pages 插件会自动抓取文件的第一行一级标题（如 `# 项目使用手册`），作为这一页的 `title` 变量。
3. **主题导航生成逻辑**：Hux 主题的顶部导航栏是根据 `_includes/nav.html` 动态生成的。它会遍历全局的 `site.pages`，**只要某个页面存在 `title` 属性，且未显式声明 `hide-in-nav: true`，就会被输出到导航栏里**。

## 解决方案

解决此问题的核心思路是阻止 Jekyll 将其判定为公开页。我们采用了**全局排除法（方案一）**作为首选：

### 方案一：通过配置全局排除（当前项目采用方案）

对于不需要编译为网页的纯项目说明目录，直接在底层的 Jekyll 配置中将其忽略。
修改根目录的 `_config.yml`，向下寻找 `exclude` 数组并在其中添加需要忽略的目录名：

```yaml
exclude:
  - docs # 添加这一行阻止 docs 被编译
  - node_modules
  - Gruntfile.js
  - package.json
  # ...其他忽略项
```

_优点_：一劳永逸，此目录下的所有新增说明文件都不会再去污染站点页面和导航。

### 方案二：利用下划线前缀规范隐藏

Jekyll 会自动略过名称以下划线 `_` 开头的目录（这被视为系统保留或组件目录）。
直接将文件夹重命名为 `_docs` 即可脱离被扫描成网页的命运。

### 方案三：单文件隐藏属性

如果确实需要将页面编译为 HTML（希望用户能通过特定链接访问），但仅仅不想它出现在导航栏。可以在对应 `.md` 文件顶部手动添加 Front Matter 加入隐藏属性：

```yaml
---
hide-in-nav: true
---
```
